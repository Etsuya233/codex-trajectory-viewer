# 自动历史与子代理目录验证

在 Windows 11 和 Microsoft Edge 的生产构建验收。真实会话按只读打开，错误模拟使用隔离的合成会话。

| 检查 | 结果 |
|---|---|
| 自动分页及锚点 | 合成会话连续两次向上滚动，已加载摘要从 50 到 100 再到 110。原首条事件在两次翻页后各保留在滚动视口相对顶部 60 px 处。表格分别挂载 48、45 条事件行。 |
| 去重及终止 | Edge 网络观察到两个不同的历史游标各请求一次。历史耗尽后按钮不可用，继续上滚不再请求。程序化补偿不触发下一页。 |
| 加载失败与重试 | 临时阻断历史请求，界面显示「重试加载更早」。解除阻断后重试同一游标，加载成功并保留锚点。 |
| 独立子代理列表 | 合成会话首屏无代理事件，列表仍找到早期派发与等待共同引用的单个 UUID，并显示未知 ID 条目。父列表可折叠、再次展开。打开子会话后返回，目录仍展开，父视口第一条可见记录及 300 px 滚动位置恢复。 |
| 按需网络访问 | 展开目录和滚动历史时未请求详情及子会话。点击目录条目后才有子会话请求。工具检查器打开时请求参数，切换到结果后另发请求。 |
| 真实会话 | 使用截图对应会话复核，向上滚动后已加载 50→100 条，DOM 挂载 43 条事件行，子代理目录显示 4 个可定位条目。 |

自动分页在向上滚动进入距顶部 120 px 的区域时触发一次。活跃筛选和全会话搜索保留手动翻页。历史游标、索引状态、请求中和失败状态控制继续加载。目录基于当前父会话的完整索引，UUID 去重并在索引进度变化后刷新，子会话文件在点击条目后独立访问。

`npm run build`、`npm run typecheck` 和 `npm test` 均通过，共 14 项测试。新增测试覆盖首屏外代理、去重、无法定位、增量解析和子会话文件缺失时的目录读取。
