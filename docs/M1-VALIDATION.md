# M1 验证记录

M1 可在本地网页打开指定的 Codex 会话，按轮次浏览最近 50 条摘要，在右侧检查器展开参数、结果和原有的思考摘要。启动步骤见 [README](../README.md)。

## 真实会话与浏览器交互

2026-11-27 在 Windows 11 10.0.26300、AMD Ryzen 7 7735H、28 GiB 内存、Node.js 24.18.0 和 Microsoft Edge 158.0.4370.33 上验证生产构建。真实样本包含 460 条可解析 JSONL 记录，大小 1,731,946 字节。样本文件、输出及截图保留在本机验证范围内。

- 通过页面的会话 ID 表单打开真实会话。表格显示 50 行、4 个轮次分组，其中 34 行工具调用带已配对结果，1 行为思考摘要。
- 点击同一调用的参数与结果标签，分别加载正文。点击思考摘要后显示日志中的可读正文。初始页面没有详情面板，参数/结果按各标签单独请求。
- 收起最后一组后表格从 50 行变为 43 行，重新展开后恢复。验证了已加载摘要的搜索空态和「记录时间」模式切换。
- 在 1,411 CSS 像素宽的视口检查样式。时间线为 51 px 高、表头为 30 px 高，中文事件列为 84 px，内容列使用剩余宽度。表头色取自 DSH 的设计令牌，详情使用原有右侧拆分布局。

## 首屏计时

首屏指标从浏览器导航时间原点，到 React 提交表格后第二次 `requestAnimationFrame` 回调，每次确认 50 行已进入页面。该采样涵盖网页导航、应用装载、摘要请求与渲染，受浏览器调度影响。内容区从最近记录起始，可滚动浏览本批 50 行。可在地址中追加 `&measure=1`，从表格的 `data-first-rows-ms`、`data-render-committed-ms` 和 `data-summary-request-ms` 读取浏览器采样。

| 场景 | 样本（毫秒） | 中位数（毫秒） |
|---|---|---:|
| 新 Node 服务和新页面导航，三个端口各首次打开真实日志 | 2946、2621、1019 | 2621 |
| 复用同一 Node 服务和 Edge 标签，重新加载页面 | 2609、518、1634、772、935 | 935 |
| Node HTTP 客户端独立请求摘要并解析 JSON，复用已启动服务 | 125、58、54、53、35、24、36 | 53 |

新服务采样复用了 Edge 进程和操作系统文件缓存。服务已开始监听后才导航，采样未覆盖 Node 启动时间。HTTP 响应使用 `no-store`，热开指复用服务和浏览器环境。M1 无持久索引，每次打开时按文件名定位并读取选定日志的尾部。

第二批前台 Edge 样本中，摘要请求耗时为 215、84、108、97 ms，React 提交时间为 1381、921、860、544 ms，首屏计时为 1388、1937、864、1538 ms。第二次和第四次各有约 1 秒的提交后帧回调等待。API 返回 33,871 字节。真实样本热开中位数低于 1 秒，单次结果波动较大。已有索引条件下的 1 秒目标留待索引实现后验收。

## 代码与数据检查

- `npm run build`、`npm run typecheck`、`npm test` 均通过。6 个合成测试覆盖按 ID 查找和归档、并行调用及状态、跨 64 KiB 分块的大 UTF-8 记录、半行、详情分块、跨首屏的独立结果、读取上限和过期偏移。
- 文件定位只遍历会话目录的名称。读取轨迹和详情时只打开对应会话的文件，以字节偏移和记录内容摘要校验详情。请求采用同源回环 HTTP，工具内容以文本形式渲染。
- 首屏逆序按 64 KiB 读取选定日志的后缀，最多扫描 8 MiB。触及上限时在工具栏标记，无法取得完整一行的记录可能略过。详情分页单次最多返回 32,768 UTF-16 代码单元，并避开代理对边界。
- 调用与结果按记录的 `call_id` 关联。待补齐的调用标为「未见结果」，首屏之外的调用结果可以作为独立记录显示。末尾无换行的记录等补齐后才纳入下一次读取。未知数据保留原始记录入口，思考摘要仅来自已有的 `summary_text`。
