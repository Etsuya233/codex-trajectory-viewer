# Codex Trajectory Viewer 产品需求文档

- 日期：2026-11-27（Asia/Shanghai）
- 状态：M2 本地网页验证完成，M3 Desktop 集成待实现
- 需求来源：聊天「查找 Codex 轨迹查看器」及后续方案讨论
- 来源聊天：codex://threads/01a21abd-f8d0-7903-8869-651ef368de37

## 1. 背景与目标

用户需要在 Codex Desktop 内查看执行轨迹，包括工具参数、工具结果、已保存的思考摘要、轮次与时间线。现有 Codex Trajectory 插件的界面不符合使用习惯，加载时曾长时间停留在 Waiting for trajectory data。

前序聊天记录了约 60～90 秒的读取耗时，并定位到子代理汇总及重复会话扫描。本次方案核对确认现有插件的版本计算仍调用子代理用量汇总；历史性能数字不是本项目的基准测试结果。

目标是保留 DeepSeek Harness Trajectory 的主要视觉与操作方式，提供快速、可解释、可独立验证的 Codex 本地轨迹查看体验。

## 2. 用户与核心场景

主要用户是需要检查自身 Codex 执行过程的开发者。

1. 打开指定聊天，立即看到最近轮次及工具执行情况。
2. 展开一次工具调用，查看完整参数、结果或错误，并定位原始记录。
3. 查看日志中已保存的思考摘要，理解可观察到的执行过程。
4. 向上加载历史或搜索当前会话，定位失败、长耗时和指定工具。
5. 查看正在运行的聊天，新记录自动追加，阅读历史时不被强制滚动打断。
6. 点击子代理链接，单独查看该子代理，再返回父会话原来的位置。

## 3. 产品边界

### 首个可用版本包含

- 指定会话打开与轻量会话选择。
- DSH 风格的轮次分组、轨迹表格、时间线、折叠、工具详情和搜索。
- 消息、工具调用及结果、错误、思考摘要、压缩边界的展示。
- 历史分页、增量更新、大输出按需加载。
- 子代理独立打开及父会话返回。
- 当前会话有数据依据的 Token 和耗时信息。
- 本地网页运行；Desktop 内置浏览器使用。

### 后续集成阶段包含

- MCP Apps 面板入口及宿主提供的当前聊天绑定。
- 面板关闭重开、刷新、错误恢复与插件打包。

### 本期不包含

- 主会话递归读取子代理、合并子代理轨迹或汇总子代理 Token。
- 费用估算、额度监控、悬浮窗、远程同步和多用户服务。
- 修改 Codex 日志、执行或重放工具调用。
- 还原日志中不存在的模型思考内容或精确请求信息。
- 完整复刻 Harness 的会话运行时及全部功能。

## 4. 功能需求

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-01 | 打开指定会话 | 可通过明确的会话 ID 打开；不存在时明确提示，不静默切换到最新会话 |
| FR-02 | 会话选择 | 提供标题或 ID 等可用元数据；列表发现与轨迹加载分离，不为展示列表解析所有日志全文 |
| FR-03 | 保留 DSH 体验 | 以固定上游提交为参考，对照检查轮次、表格、时间线、搜索和详情交互；适配差异有记录 |
| FR-04 | 工具调用配对 | 以调用 ID 等原始标识关联调用与结果，正确处理并行、失败、缺失结果与仍运行状态 |
| FR-05 | 后台执行状态 | 区分工具返回运行中与进程最终结束；有明确关联信息时展示后续输出，不把首次返回当作任务完成 |
| FR-06 | 参数与结果详情 | 首屏传输摘要；展开后读取完整可用内容，大输出分段加载，明确标记截断或缺失 |
| FR-07 | 思考摘要 | 展示日志中已有的可读摘要；不存在时不生成替代内容 |
| FR-08 | 历史分页 | 向上加载不重复、不漏掉已支持格式的记录，保留滚动位置；部分轮次可在历史加载后补齐 |
| FR-09 | 实时更新 | 新完整记录追加展示；半行 JSON 不报永久损坏；正在查看历史时不强制跳到底部 |
| FR-10 | 搜索与筛选 | 区分已加载内容搜索与全会话搜索；可按工具名及错误筛选；结果可跳到对应记录 |
| FR-11 | 子代理导航 | 主会话仅使用自身派发、等待及返回记录；点击后才加载子代理；返回时恢复父会话位置 |
| FR-12 | 会话统计 | 各会话分别统计；缺失值显示未知；首屏不等待完整统计；统计注明覆盖范围 |
| FR-13 | 压缩与继承 | 标明可识别的压缩和继承边界；继承历史与本会话执行区分，防止重复计数 |
| FR-14 | 原始记录 | 未知事件保留通用展示和原始 JSON 入口；展示详情可以追溯到来源记录 |
| FR-15 | 加载与错误反馈 | 区分定位会话、读取、索引和错误状态；失败有重试，不无限停留在笼统等待提示 |
| FR-16 | Desktop 面板 | 原生面板集成阶段验证当前会话识别、关闭重开和刷新；未提供身份时要求明确选择会话 |

## 5. 性能与可靠性

以下是待验证的目标，不是现有测量结论。

- 在用户本机、已有索引的条件下，打开会话到最近 50 条摘要可见，目标不超过 1 秒。记录日志大小、记录数、软硬件环境与多次测量结果。
- 冷启动和首次打开大日志分别测量；先显示可读取的最近内容，再补齐必要索引，不把完整统计作为首屏前置条件。
- 一次主会话轨迹加载不打开子代理日志。子代理更新不使主会话轨迹缓存失效。
- 正常追加时只读取新增字节，不重复解析整份日志；没有变化时不做全量扫描。
- 长列表采用虚拟化或等效的有界渲染；工具大输出不能使首屏响应体和 DOM 随日志总量增长。
- 处理半行写入、无效行、文件截断和替换；需要重建时只重建受影响会话。
- 默认只读日志，本地服务仅监听回环地址；索引及真实会话内容不提交到 Git。
- 浏览器展示工具结果时按不可信文本处理，禁止直接执行其中的 HTML 或脚本。

## 6. 数据语义

内部模型至少覆盖 Session、Turn、Event、ToolCall、ToolResult、Usage 和子代理链接。记录需要稳定 ID、来源位置及可用时间戳；前端展示模型与原始 Codex 格式分离。

- 使用稳定来源标识去重，不能单凭消息文本判定重复。
- 调用与结果允许跨页关联，未加载结果不等同于执行失败。
- 时间线区分观察到的时间点和可确认的持续时间，不能把所有相邻事件间隔都标为模型思考耗时。
- Token 数据区分累计值与增量值，避免重复求和；无法可靠解释时保留原始值并注明。
- 用户轮次、模型步骤和工具调用分别表达；日志不足以确定步骤时不伪造精确步骤编号。
- 子代理关系优先来自当前会话已有派发结果；无法解析目标时显示不可定位状态，不扫描全部日志猜测。
- 继承或分段日志的读取规则应与子代理加载分开，必要的来源解析不等于递归加载子代理。

## 7. 建议实现结构

这部分是技术方向，具体库选择不作为产品验收要求。

```text
Codex 本地日志
    ↓ 只读定位与增量解析
会话索引 + 标准化事件模型
    ↓ 分页 / 详情 / 搜索 / 更新接口
DSH 展示组件适配层
    ↓
本地网页 / Desktop 面板
```

- 前端采用 React + TypeScript，保留 DSH 展示组件、样式及交互，替换 Harness 的会话绑定、数据订阅和宿主依赖。
- 本地服务采用 Node.js，日志解析与 HTTP/MCP 传输解耦。
- 索引可重建，记录文件身份、偏移及解析版本；内存或持久化方案通过大日志样本验证后选择。
- 先支持本地网页，用相同数据层接入 MCP Apps；不能假定更换传输协议会解决日志扫描问题。
- 上游源码固定提交保存于 `references/deepseek-harness`，提取代码时保留许可与来源记录。

## 8. 里程碑与验收

### M1：完整的最小链路

指定一个真实会话，读取最近记录并显示 DSH 风格轨迹；可展开工具参数、结果及已有思考摘要。同步验证上游组件依赖剥离和首屏耗时。交付可运行本地网页、运行说明与适配差异记录。

### M2：日常可用

完成分页、增量刷新、搜索、子代理导航、原始记录、大输出和错误恢复。使用短会话、长会话、并行调用、后台命令、失败调用、半行写入、压缩/继承和子代理等样本验收。测试数据使用脱敏或合成样本。

特别检查：打开父会话不读取子代理文件；新增记录只读取新增字节；历史与实时数据重叠时无重复；调用跨页仍能关联结果。

### M3：Desktop 集成

在 Desktop 内验证本地网页，并完成 MCP Apps 面板接入、当前会话绑定、面板重开、重试和插件打包。同一会话在网页与面板显示一致；宿主集成失败时本地网页仍可独立使用。

## 9. 风险与待验证事项

| 风险 | 处理方式 |
|---|---|
| DSH 组件跨包依赖较多 | 固定版本，先完成最小组件依赖审计；保留界面但替换宿主绑定 |
| Codex 日志格式变化 | 解析层独立、未知事件可见、维护脱敏样本和解析版本 |
| 分段、继承与压缩语义复杂 | 第一阶段采样确认，明确支持范围，不静默漏记或重复统计 |
| Windows 文件变化通知不稳定 | 变更通知结合低频文件状态检查，使用偏移与文件身份校验 |
| MCP Apps 宿主握手或缓存问题 | 独立网页作为诊断入口，分别验证数据读取和宿主桥接 |
| 冷启动大日志影响首屏 | 尾部有界读取与索引补齐分离，分别记录冷、热启动指标 |
